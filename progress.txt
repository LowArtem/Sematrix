## Codebase Patterns
- Derive `GET /api/notes` hashtag parsing from the shared tag-name validator so search-time `#tag` extraction stays aligned with backend tag normalization rules.
- Treat a search hashtag as valid only when it ends at the query boundary or common closing punctuation, so invalid tokens like `#bad-tag` stay in free text instead of being partially stripped into a false tag filter.
- Keep the required repository scaffold protected by a lightweight pytest that asserts the fixed top-level and backend layer paths exist.
- Keep the PRD integration branch name distinct from the epic branch namespace; Git cannot create a branch like `foo` once epic branches already use `foo/...`.
- Guard Docker Compose changes with both `docker compose config --services` and a real `docker compose up --build` smoke test against the backend health route and frontend root.
- For localhost-only Compose exposure, use long-form `ports` mappings with `host_ip: 127.0.0.1` and verify the rendered `docker compose config` output in tests.
- For bind-mounted Postgres data under `./data/postgres`, set `PGDATA` to a child directory so `initdb` can initialize cleanly against the fixed host path.
- For Ollama GPU passthrough in this repo, prefer `deploy.resources.reservations.devices` over a top-level `gpus` key because the current Compose validator rejects `services.<name>.gpus` during `docker compose config`.
- For automatic Ollama model availability, use a one-shot `ollama-init` service that shares `./data/ollama`, waits for the API, and gates model-dependent services with `condition: service_completed_successfully`.
- When Ollama model compatibility outruns usable Docker tags, pin the official `ollama/ollama` image by digest in Compose so `ollama` and `ollama-init` stay reproducible while still matching the required model set.
- Keep Docker build context lean with a repo-root `.dockerignore`, especially excluding `frontend/node_modules` and `frontend/dist` so local frontend artifacts do not leak into image builds.
- For database-foundation stories, verify `alembic upgrade head` against a freshly created scratch PostgreSQL database through `docker compose run --rm --no-deps backend ...` instead of trusting file-only migration scaffolding.
- When an Alembic migration manually creates a PostgreSQL enum before table creation, use `postgresql.ENUM(..., create_type=False)` on the table column to avoid duplicate `CREATE TYPE` attempts during `op.create_table(...)`.
- Create the scratch validation database explicitly inside the Compose Postgres service before running `alembic upgrade head`, since Alembic will not create the target PostgreSQL database for you.
- Wait for `pg_isready` inside the Compose Postgres container before scratch-database `psql` setup, because the container may report as started before PostgreSQL accepts connections.
- In SQLAlchemy declarative models, do not use `metadata` as a Python attribute name; map the database column with an alternate attribute such as `metadata_json = mapped_column("metadata", ...)`.
- For schema/index stories, validate the final PostgreSQL indexes from `pg_indexes` against a scratch migrated database instead of assuming SQLAlchemy/Alembic declarations rendered exactly as intended.
- Keep Celery tasks in dedicated `app/workers` modules registered via the Celery app, and keep host-side backend-foundation tests source-based when they only need to verify architectural wiring.
- Keep backend ENV parsing centralized in `app/core/config.py` and have FastAPI/Celery bootstrap code consume shared settings there instead of scattering raw `os.getenv(...)` calls across entrypoints.
- Keep FastAPI error shaping centralized in `app/api/errors.py`; register global handlers from app bootstrap so 404/409/413/415/422/500 responses and validation payloads stay in one `ApiErrorDto` format.
- Keep structured logging context centralized in `app/core/logging.py`; bind API `X-Request-Id` in middleware and Celery `task_id` in worker bootstrap so route/task code can stay focused on domain work.
- Keep request-scoped SQLAlchemy sessions in `app/api/dependencies.py` and inject repository-backed domain services from there so FastAPI route handlers stay HTTP-only.
- Keep tag validation and normalization centralized in `app/domain/tags.py` so request DTOs and later save/domain flows reuse the same lowercase/no-spaces/allowed-characters rules.
- Keep note-list query parsing in `app/domain/notes.py` so `#tag` extraction and normalized-tag filtering can be reused later when search ranking changes behind the same `GET /api/notes` contract.
- Keep Tiptap save parsing in a dedicated domain helper so note-save flows reuse one source for flattened text, `assetId` extraction, and normalized `http/https` link extraction before syncing `note_assets` and `note_links`.
- Keep the Draft-versus-Processing decision in a shared domain helper so save flows and later Draft-cleanup logic can reuse the exact meaningful-content rule.
- Keep Draft reset defaults in a shared domain helper so empty saves clear `summary`, `search_text`, `embedding`, and warning/error fields consistently whenever a note falls back to `Draft`.
- For SQLAlchemy relationships that rely on database `ON DELETE` behavior, set `passive_deletes=True` on the ORM relationship so note/asset cleanup does not try to null non-nullable foreign keys before the database cascade runs.
- For file-backed asset uploads, validate MIME/size in the domain service and unlink the just-written file on database rollback so `./data/assets` stays consistent with `assets` and `note_assets`.
- For `GET /api/tags`, keep tag counting in the repository via an outer join on `note_tags`, and when `q` is present use ordering that moves substring matches first without filtering the non-matching tags out of the paginated result set.
- Create `pipeline_runs` inside the same note save/reindex repository transaction after flushing synchronized `note_assets` and `note_links`, so snapshots capture DB-assigned link IDs before dispatching background work.
- Keep pipeline stage selection in `app/domain/pipeline.py`, and let the worker-side orchestrator load `pipeline_runs` snapshot state from the repository before it schedules any Celery `group/chord` work.
- Keep stage guards in `app/infra/pipeline.py`, and have worker stages reload `pipeline_run_id` snapshot state there so they validate `index_version`/`snapshot_hash` and query live assets or links only through snapshot-filtered IDs.
- Keep final note finalization in `app/infra/pipeline.py` with an injected `app/infra/ollama.py` client so `finalize_pipeline` rebuilds `search_text`, embeddings, and final summary from durable PostgreSQL results while smoke tests can swap in fake local-model clients.
- Keep pipeline failure handling in `app/infra/pipeline.py` so `pipeline_failed` can revalidate runtime state, downgrade non-critical stage failures into note warnings, and fall back to a shared finalizer or Error write from one place.
- Keep the fixed Celery retry policy encoded on the worker task definitions themselves so link processing gets 3 total attempts with exponential backoff while OCR/image-caption get 2 total attempts without drifting from the spec.
- For Draft TTL cleanup, evaluate emptiness from parsed `content_json` with the shared meaningful-content rule instead of raw `note_assets` rows alone, so abandoned pre-save uploads remain cleanup-eligible while orphaned asset files can still be removed.
- Keep save-time title and fast-summary generation behind an injected `app/infra/ollama.py` client in `NoteService`, so meaningful saves can prefill card data and persist non-fatal generation warnings while tests swap in fakes without touching route handlers.
- Keep OCR calls in `app/infra/ocr.py`, and have OCR/caption stages update only their own columns plus stage-specific warnings on shared `asset_processing_results` rows so reruns do not erase sibling stage outputs.
- Keep image caption generation in `app/infra/ollama.py` and inject that client into `PipelineStageRunner`, so `process_image_caption` can reuse the configured vision model while tests swap in fakes without moving caption logic into Celery tasks.
- Normalize extracted note URLs before syncing `note_links` by lowercasing scheme/host, removing fragments/default ports, and sorting query params so plain-text URLs and link marks collapse onto the same `normalized_url`.
- Keep SSRF-safe link fetching in `app/infra/link_fetcher.py`, with a no-redirect opener plus per-hop scheme/port/DNS revalidation and streamed size/time limits before any link-specific parser touches the body.
- Keep YouTube Data API calls in `app/infra/youtube.py`, and persist both structured metadata plus derived index text/summary on `link_processing_results` so finalization can consume official API output without HTML scraping.
- For `youtube_channel` links, keep the YouTube Data API as the default path and use the shared SSRF-safe fetcher only for retryable API-failure fallback, recording that downgrade as a warning instead of changing the primary integration design.
- Keep text-file link handling in `app/infra/pipeline.py` on top of the shared safe fetcher, enforce `MAX_TEXT_FILE_MB` separately from the fetcher's global body cap, and fall back to a warning-backed heuristic summary when the non-thinking Ollama summary call fails after text extraction succeeds.
- Keep generic webpage link handling on top of the shared safe fetcher, extract main text in `app/infra/web_pages.py` with trafilatura first and readability-lxml fallback, and fall back to a warning-backed heuristic summary when non-thinking page summarization fails after extraction succeeds.
- Mirror per-object non-critical OCR/link/caption warnings onto `notes.processing_warnings` as soon as a stage writes its durable result, so note detail polling can surface warnings before finalization while final Ready-state deduplication still relies on the stage tables.
- Build `search_text` through the shared domain helper in both phases: save-time writes the fast document from currently available note fields, and finalization rebuilds the full document from durable OCR/link outputs without feeding `note.summary` back into it.
- Route finalizer task exceptions through the shared pipeline failure handler too, so zero-stage/direct-finalize runs still mark notes `Error` on embedding/finalization failures instead of getting stuck in `Processing`.
- Keep note lexical search in `app/infra/notes.py` on top of stored `notes.search_tsv`, and reuse the same RU+EN `websearch_to_tsquery` expression for both `@@` matching and `ts_rank_cd` ranking.
- Keep hybrid-search RRF fusion in a shared domain helper, reuse one `RRF_TOPN` value for both lexical and vector candidate preselect queries after filters, and paginate only after the fused `score desc, updated_at desc, id desc` ordering is built.
