## Codebase Patterns
- Keep the required repository scaffold protected by a lightweight pytest that asserts the fixed top-level and backend layer paths exist.
- Guard Docker Compose changes with both `docker compose config --services` and a real `docker compose up --build` smoke test against the backend health route and frontend root.
- For localhost-only Compose exposure, use long-form `ports` mappings with `host_ip: 127.0.0.1` and verify the rendered `docker compose config` output in tests.
- For bind-mounted Postgres data under `./data/postgres`, set `PGDATA` to a child directory so `initdb` can initialize cleanly against the fixed host path.
- For Ollama GPU passthrough in this repo, prefer `deploy.resources.reservations.devices` over a top-level `gpus` key because the current Compose validator rejects `services.<name>.gpus` during `docker compose config`.
- For automatic Ollama model availability, use a one-shot `ollama-init` service that shares `./data/ollama`, waits for the API, and gates model-dependent services with `condition: service_completed_successfully`.
- When Ollama model compatibility outruns usable Docker tags, pin the official `ollama/ollama` image by digest in Compose so `ollama` and `ollama-init` stay reproducible while still matching the required model set.
- Keep Docker build context lean with a repo-root `.dockerignore`, especially excluding `frontend/node_modules` and `frontend/dist` so local frontend artifacts do not leak into image builds.
